# v0.5 组合集成实施说明

## 一、版本目标

v0.5 解决“如何把 OpenClaw、WeKnora、OpenViking 组装成一个产品，同时不给三套上游制造长期 Fork”的问题。

实现策略：

```text
OpenClaw = Host + Agent Runtime
WeKnora = Knowledge Engine
OpenViking = Memory + Skill Engine
自研层 = Plugin + Adapter + Ontology/Retrieval Governance
```

## 二、OpenClaw 扩展

新增两个独立插件：

```text
integrations/openclaw/knowledge-plugin
integrations/openclaw/openviking-plugin
```

二者使用 OpenClaw 正式公开的：

- `definePluginEntry`
- `registerGatewayMethod`
- `session.controls.registerControlUiDescriptor`
- `defineControlUiPlugin`
- `host.ui.registerPage`
- `host.ui.registerNavigation`

不修改 OpenClaw `ui/src/app-routes.*`、Agent Loop、Session、Tool Runtime、MCP Runtime。

### Knowledge Plugin 数据通路

```text
Browser
  -> leeclaw.knowledge.*
  -> plugin runtime
  -> WeKnoraClient
  -> WeKnora API
```

### Memory/Skill Plugin 数据通路

```text
Browser
  -> leeclaw.memory.* / leeclaw.skills.*
  -> plugin runtime
  -> OpenVikingClient
  -> OpenViking API
```

## 三、为什么没有 iframe WeKnora/OpenViking

用户要求 Knowledge 管理真正成为 OpenClaw 的一部分。因此 v0.5 重新组织 OpenClaw 原生管理页，只复用上游后端能力和行为规则。

这同时避免：

- 双层导航；
- 三套品牌并列；
- iframe 会话/安全策略耦合；
- 直接复制整套 Vue/React 源码造成前端 Fork。

## 四、为什么浏览器不能直连上游

浏览器如果直接写：

```text
/api/v1/knowledge-bases
/api/v1/skills
```

那么 WeKnora/OpenViking 的 API 变化会污染所有 UI 文件。

v0.5 强制：浏览器只认识 Gateway Contract。`scripts/verify-v0.5.sh` 会扫描 browser 目录，发现 `/api/v1` 或上游 Base URL 即失败。

## 五、WeKnora 权限

v0.5 不复制 WeKnora 的 RBAC。

Knowledge Adapter 可透传：

```text
Authorization
X-API-Key
X-Tenant-ID
X-External-User-ID
```

Graph API 的授权委托进一步支持 `X-External-User-Token`。

按钮可见性只是 UI；真正的知识库访问、成员、分享、操作权限始终由 WeKnora 后端判定。

## 六、OpenViking Memory / Skill

OpenViking 官方 context-engine 插件继续独立安装，并设置：

```text
plugins.slots.contextEngine = openviking
```

推荐：

```json
{
  "recallTargetTypes": ["user", "agent"],
  "enableAddResourceTool": false
}
```

这是为了保持：

```text
企业 Knowledge -> WeKnora
个人/Agent Memory -> OpenViking
Skill -> OpenViking
```

避免同一制度、文档在两个知识引擎重复成为权威源。

## 七、Skill 加载策略

OpenViking `/api/v1/skills` 是管理面；Agent Runtime 已可以使用官方 OpenViking 工具按需加载：

```text
ov_search -> 找候选 Skill / L0/L1
ov_read / ov_multi_read -> 读取 L2 / SKILL.md
```

v0.5 不把 Skill 批量复制到 OpenClaw 本地目录。

## 八、本体与 GraphView

本体治理保持 v0.4 设计：

- 不进入 WeKnora ENTITY Label；
- Registry 版本不可变；
- KB active/pinned binding；
- Graph API 稳定；
- Knowledge UI 同时显示实体图和本体图。

## 九、上游升级 SOP

1. 拉取新的 OpenClaw/WeKnora/OpenViking 源码；
2. 更新 `compatibility/upstreams-v0.5.json` 的候选版本；
3. 执行 `check-v0.5-upstreams.sh`；
4. 执行 `make verify`；
5. 在干净 OpenClaw 上重新执行 `apply-integration.sh`；
6. 运行真实服务 E2E：登录、KB list/create、文档、Wiki、实体/本体图、成员/分享、Memory、Skill；
7. 若失败，只在对应 Adapter/Plugin 边界修复；
8. 输出 Upstream Impact Report；
9. 上游源文件修改数默认必须为 0。

## 十、v0.5 验证边界

本仓库可离线验证 Go Core、JS Adapter、插件语法、浏览器隔离和源码 Contract。

OpenClaw 完整 Control UI bundle 依赖其 pnpm 工作区。若构建环境无法获取 npm 依赖，只能标记“源码/合同验证通过，完整 OpenClaw bundle 待具备依赖缓存或网络的 CI 复测”，不能把它写成已通过。
